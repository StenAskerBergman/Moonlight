| > 1.1.0 - Write Direction Principle 
|------------------------------------------------------------------
| - All Documentation must be written in Top to Bottom Direction.
|	
|	example:
|
|		1. Third Comment
|
|		2. Second Comment
|		
|		3. First Comment
|
|	Here we clearly see the first thing being read is the first
|	comment, then the second comment and then the third comment.
|
|	This is the direction that must be followed, to reduce any1
|	trying to find the latest updates, it's always at the top.
|
|	This change allows us to fastly find the latest updates. By
|	reading the file preview from the inspector. Reducing over all 
|	information absorbtion time for the reader / user / developer.
|	
|	However, if some documentation is excempt from this rule due 
|	too being long, or for creating unclear reading patterns. if
|	so then it needs to be stated at the top of the documentation.
|	
|	Example:
|	
|		Write:	
|
|			1. Write Direction: Topside - From Top To Bottom - FTB - WRITE FROM TOP
|			2. Write Direction: Botside - From Bot To Top - FBT - WRITE FROM BOT
|	
|		Read: 
|	
|			1. Read Direction: Topside - From Top To Bottom - FTB - READ FROM TOP
|			2. Read Direction: Botside - From Bot To Top - FBT - READ FROM BOT 
|
|	This is always at the top of the documentation, so the reader
|	can quickly find the reference location of the latest updates.
